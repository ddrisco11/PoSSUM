# Local adapter training protocol

New runs default to `data/assembled-v2-no-manifesto`, excluding policy-mapped Manifesto passages: 7,598 expert-fit, 1,967 calibration, 2,195 router-fit and 1,656 validation examples. Derive it once with `scripts/exclude_manifesto.py`. This revision has not yet been trained; see [passage-level review](dataset-review.md).

The completed historical run used 7,652 expert-fit, 1,967 calibration, 2,195 router-fit and 1,899 validation examples. Historical test identities and their leakage closure are excluded. Run inputs are copied once and checked against SHA-256 hashes on every resume. The development union must not be repartitioned with the pilot splitter.

Mistral uses a pinned 4-bit MLX base checkpoint and rank-8 query/value LoRA in its last four layers (425,984 trainable parameters). Training minimizes class-balanced binary cross entropy over the exact left/right next-token scores, with Adam at 5e-5, one deterministic shuffled pass, zero adapter dropout and activation checkpointing. This objective trains discrimination between the two candidates, rather than full-vocabulary language modeling.

BERT uses rank-8 query/value LoRA throughout its encoder and a trainable two-class classifier, with AdamW at 2e-4, weight decay 0.01, batch size eight and class-weighted cross entropy. Its base weights remain frozen. GLiNER and Qwen remain frozen throughout this run. BGE embeddings are frozen.

Mistral saves versioned adapter and optimizer checkpoints every 50 examples; two recovery versions are retained. The first update-replay test must reproduce adapter parameters within 1e-6 after restoring optimizer and adapter state. Zero dropout and a deterministic example order avoid random draws during Mistral updates. BERT saves adapter, optimizer, example offset, CPU/MPS RNG states and input hash every 200 examples. Both models verify serialized adapter tensors before publishing their local training artifact.

Scoring checkpoints use atomic replacement after each batch. Resume validates input hashes, trained adapter metadata and ordered IDs. Interrupted work can repeat the last unsaved batch. The process lock prevents concurrent drivers for the same run. Only one backbone is loaded at a time. Sustained work waits for AC power by default; a fixed overall cutoff is preserved on resume. Stage limits permit a partial adapter to proceed to evaluation, with the actual example count and partial status recorded.

Temperatures are fitted only on calibration data. A regularized BGE logistic self head is fitted only on expert-fit data, then frozen. Mixture fits use only router-fit data. Candidates include equal averaging, a compact BERT/GLiNER equal mixture, learned fixed weights, a linear neural router, and a router with a self contribution capped at 25%. Learned mixtures use three initialization seeds, weight decay and a penalty toward uniform mixture weights. Validation log loss selects among the declared ensemble candidates; individual experts and leave-one-expert-out averages are also reported. The reserved test data are not scored in this development pipeline.

The export stores calibration parameters, backbone revisions, mixture weights, self head, selection rule and relative adapter locations. Fresh-file router reloads must reproduce evaluation predictions. `scripts/predict_option_a.py` loads the selected export and executes its required components sequentially. This is a research prototype: all training labels are weak or synthetic, validation supports development selection only, and neutral/nonpolitical detection and fresh human evaluation remain unresolved.

After the main evaluation completes, `python scripts/evaluate_adapter_diagnostic.py --run runs/option-a-20261017` applies the saved calibration and all saved heads to the 97 human-labeled sentences in the public IBC diagnostic. It rejects exact development overlap, verifies adapter hashes, preserves the original deadline, and does not fit or select anything on these labels. The sample has already been inspected during earlier development and lacks book/author grouping, so its report is a transfer diagnostic rather than a fresh final test. The locked tests remain unopened.

`python scripts/compare_frozen_adapters.py --run runs/option-a-20261017` performs the matched development comparison after the main run. It uses a frozen BERT mean-pooling/logistic-probe baseline and the identical Mistral base checkpoint without its adapter, recalibrating each on the same calibration data. The BERT comparison is between full classifier recipes, while the Mistral comparison isolates its adapter plus calibration. Scores resume from atomic checkpoints, the original deadline still applies, and paired group-bootstrap differences are descriptive development estimates. Run it sequentially after any human-text diagnostic to avoid concurrent GPU backbones.

The final BERT recovery audit reproduced a discarded update exactly after restoring its adapter, AdamW state and CPU/MPS RNG. Original trained files were unchanged. Mistral also passed exact one-update optimizer recovery. All development IDs and groups remained disjoint, input hashes matched the original snapshot, and every score cache was complete, aligned and finite. [Verification record](../reports/export-verification.json).

Add `--diagnostic` to the matched-baseline comparison to evaluate the same development-fitted recipes on IBC. The matched reference is saved separately under `frozen-export/`, while the original routing export stays under `export/`. Both paths passed raw-text reload checks. `scripts/package_adapter_export.py` creates a local inference-only adapter bundle with file hashes and tested dependency versions; base models are cached separately.
